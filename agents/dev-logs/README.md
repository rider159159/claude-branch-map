# dev-logs/ — 每日開發紀錄

## 為什麼要寫

- 不用翻 git log 就能看「昨天 / 上週做到哪」
- 沉澱「哪一天決定 X、原因是什麼」 — 設計脈絡的長期記錄
- 新的 AI session / 人類同事接手時,讀最新一份就能跟上進度
- 對個人專案:幾週後自己回頭,能回憶起當時的取捨

## 一天一檔

- 檔名:`YYYY-MM-DD.md`(例:`2026-06-02.md`)
- 範本:`agents/templates/dev-log.md`
- 6 個固定區塊,沒事可寫的寫「無」不要刪欄位

## 何時更新

- **開始 task** → 在「進行中」加一筆
- **完成 task** → 移到「完成」,寫 commit hash
- **跟使用者 / AI Q&A** → 立刻寫進「詢問與裁決」(否則之後想不起來理由)
- **commit / push 前** → 整理「下一步」後再推

## 跟 commit 訊息的分工

| 項目 | dev-log | commit message |
|---|---|---|
| 改了什麼 | 不寫 | 寫 |
| 為什麼這樣改 | 寫 | 寫(body) |
| 考慮過的別種選擇 | 寫(詳細) | 簡述 |
| 跟使用者的對話 | 寫 | 不寫 |
| 卡在哪 | 寫 | 不寫 |
| 下一步 | 寫 | 不寫 |

## 索引(可選)

檔案多了之後,可在這個 README 補一份倒序索引:

```
- 2026-06-02 — 加 agents/ 知識庫、寫 optimization-plan
- 2026-06-01 — session 自訂標題 + tag
- 2026-05-28 — 在 VS Code 繼續對話
```
