### 詢問與裁決(AI ↔ 使用者)

- **Q**:#2 原本含「一鍵安裝」spawn 安裝腳本,要保留嗎?
- **A**:不保留。改成只顯示狀態 + 「複製安裝指令」按鈕,由使用者主動在終端執行。原因:spawn PowerShell 要處理執行原則、權限、錯誤分類,風險高、debug 痛,且 ROI 不對等

- **Q**:banner 顯示策略?
- **A**:只在 `scriptInstalled=false` 顯示,可手動 dismiss(寫進 `AppSettings.hookBannerDismissed`)。後 code-reviewer 提醒「腳本存在但 settingsRegistered=false」也是壞掉狀態,改為兩條件 OR

- **Q**:複製安裝指令的介面?
- **A**:依平台自動選(Windows 給 PowerShell、其他給 bash)。後 reviewer 提醒 hookHealth 為 null 時不應 fallback 給錯誤指令,改為平台未知時不渲染指令區塊

### 決策 / 取捨

- **不在 app 內 spawn 安裝腳本**:Windows PowerShell 的 ExecutionPolicy / signed-script / UAC 提示在不同機器表現差異大,Electron 主程序 spawn 後若 hang 或要互動,使用者無法救援。改成「複製指令到終端執行」把控制權還給使用者,出錯時錯誤訊息也直接呈現在他熟悉的 shell
- **`navigator.clipboard.writeText` 走 renderer 而非 main 程序的 `clipboard`**:既有 `copyResume` 走 main 是因為它還要先 build 指令字串,而這裡只是複製固定 install command,沒必要新增 IPC 通道。Electron renderer 的 clipboard API 在 secure context(包含 file://)可用
- **banner 條件改 `!scriptInstalled || !settingsRegistered`**:reviewer 指出腳本被手動複製但沒跑安裝器是常見 partial state,hook 仍不會運作。改成兩個任一缺失就提示,文案也改為「腳本或 PostToolUse 註冊缺一」
- **scroll-to-section 改 useEffect + ref flag**:原本用 `requestAnimationFrame` 在 `setShowSettings(true)` 同 tick 內 scroll,reviewer 指出 React 還沒 commit、節點不存在。改用 `scrollHookOnOpen` ref + 監聽 `showSettings` 的 useEffect,等 SettingsPanel 渲染完才捲動
- **`cmd.includes('branch-hook')` 字串匹配寬鬆**:reviewer 建議改 regex 比對副檔名;評估後維持原樣 — 跨平台 command 可能含完整絕對路徑,改嚴反而漏判,且非 security risk
- **handler 不加 try-catch**:與既有 handler 風格一致;但 renderer 端的 `refreshHookHealth` 加了 `hookHealthError` state,UI 上會顯示「無法檢查 hook 狀態:{msg}」而非永遠卡在「正在檢查…」
